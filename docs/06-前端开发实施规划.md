# 纸上谈网 前端开发实施规划

文档版本：V0.1
更新日期：2026-09-22

## 1. 文档目的

把冻结需求 R1–R16 的界面条款、`docs/05-前端界面设计.md`、以及 `.monkeycode/specs/2026-09-22-frontend-device-ui/` 拆成可编码、可验收的前端阶段。每个阶段含目标、小任务、产出、测试、通过基线。编码、联调、验收以本文件为准。

效力：本文件与 frontend `tasklist.md` 指导前端实施。冻结的 `docs/01`–`04`、后端 `design.md` / `tasklist.md` / `requirements.md` 不改。与冻结需求冲突时以冻结 `requirements.md` 为准。

## 2. 前端总体开发目标

1. 教师 Web：定员、开放领取、逻辑拓扑、TAP 挂接、模式切换。
2. 学生 Web：等待/满员文案；按 kind 展示 PC / 交换机 / 路由器 / TAP。
3. 学生设备舞台：交换机/路由器/TAP 底图叠加 RJ45；PC 用网卡图自带口；逻辑线指向对端设备与端口号；`physically_up` 时两侧绿点。
4. 普通模式 chat/ping，模拟模式组帧与选口，TAP 过路帧列表。
5. 教师机托管静态页；独立学生端拉起同一套学生 UI。

## 3. 核心开发原则

1. 教师机是权威；前端只展示快照与增量，不在浏览器里重判拓扑。
2. 写走 HTTP，推送走 WS 增量。
3. 学生端运行时图标只使用 `assets/icons/*.svg` 轻量手绘矢量；禁止引用 `assets/icons/source/` 里体积过大的参考 SVG。
4. 学生端底图对照 `source/` 下 PNG 绘制。教师端逻辑图标先用内联示意 SVG；用户后传思科图标后替换。
5. 开发预览只暴露前端一端口，反代 `/api` 与 `/ws`。`allowedHosts` 含 `.monkeycode-ai.online`。
6. 功能性测试全部做，覆盖界面条款与目标课堂场景。

## 4. 技术架构基线

| 层 | 基线 |
| --- | --- |
| 教师 UI | `web/teacher`，Vite + TypeScript |
| 学生 UI | `web/student`，Vite + TypeScript |
| 图标 | `assets/icons/switch.svg` `router.svg` `nic.svg` `rj45.svg` |
| 教师逻辑图标 | 前端内联 SVG，后换思科图标 |
| API | `docs/02-接口设计.md`：`/api/v1`、`/ws` |
| 独立端 | `papernet-student` 拉起学生 UI |

底图体积：机箱 / 网卡小于 40 KB，RJ45 小于 8 KB。

## 6. F0：脚手架与轻量矢量底图

### 6.1 阶段目标

教师、学生各一个 Vite 入口；学生端四张轻量 SVG 对照 PNG 手绘完成。

### 6.2 小任务

1. 建立 `web/teacher`、`web/student`：Vite、TypeScript、`allowedHosts`、`/api` 与 `/ws` 反代。
2. 对照 PNG 手绘 `switch.svg`、`router.svg`、`nic.svg`、`rj45.svg`。
3. 教师逻辑图标用几何占位，预留替换点。
4. 学生页能加载四张底图。

### 6.3 测试用例

1. 四张运行时 SVG 存在于 `assets/icons/`。
2. `switch.svg` `router.svg` `nic.svg` 各小于 40 KB；`rj45.svg` 小于 8 KB。
3. 运行时 SVG 不引用 `source/` 下参考 SVG。
4. 两端 `vite.config` 含 `.monkeycode-ai.online` 与 `/api` `/ws` 代理。

### 6.4 通过基线

F0 测试脚本全绿；学生页可见交换机、路由器、网卡、RJ45 四张轻量图。

## 7. F1：定员领取壳

依据：R1 R2 R17，F8，接口 §3。

阶段基线：未 open 展示「请等待教师确定本课设备」；领完展示「本课设备已领完，请看教师屏」；claimed 后按 `kind` 进入对应角色壳。

测试：waiting_open、claimed、full 三种画面；满员文案精确匹配。

## 8. F2：学生设备舞台

依据：前端 F1–F6，docs/05 §2–§6。

阶段基线：交换机/路由器按 `port_count` 叠加 RJ45；TAP 交换机底图叠 2 口；PC 用网卡自带口；已填对端有逻辑线与「设备+端口号」信息框；互指后两侧绿点。

## 9. F3：四类角色功能

依据：R4 R6 R7 R8 R10 R11 R13，tasklist 13.3–13.5。

阶段基线：PC 可配 IP/网关、对话、ping、组帧；交换机 MAC 表与选口；路由器每口 IP、ARP、ping、选口；TAP 过路帧列表；对端枚举不含 TAP 口。

## 10. F4：教师逻辑拓扑与模式

依据：R1 R5 R12，前端 F7。

阶段基线：拓扑使用逻辑图标（思科图标到位后替换）；互指实线、单端虚线；可挂 TAP；可切普通/模拟。

## 11. F5：托管、独立端、场景走通

依据：R15 R16，tasklist 13.6 13.7，检查点 14。

阶段基线：教师机构建并托管静态页；独立端打开学生 UI；目标课堂 PCA — 交换机1 — 路由器 — 交换机2 — PCB 可配置、普通通信、模拟传帧。

## 12. 验收总标准

1. 冻结需求界面条款全部有自动化功能测试。
2. 满员与等待文案一字不差。
3. 学生端不使用 `source/` 大 SVG。
4. 检查点 14：教师屏与学生屏走通目标课堂场景。
