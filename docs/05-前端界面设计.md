# 纸上谈网 前端界面设计

文档状态：草案（2026-09-22）
效力：细化冻结需求 R1–R15 的界面呈现与 tasklist 第 13 项。本文件独立于 V1.2 冻结的 `docs/01`–`04` 与 `design.md`。

配套规格：

- 界面需求：`.monkeycode/specs/2026-09-22-frontend-device-ui/requirements.md`
- 技术设计：`.monkeycode/specs/2026-09-22-frontend-device-ui/design.md`

## 1. 设计目标
学生端把「一台设备」画成可接线的岗位：交换机与路由器用无网口机箱作底图，网口按教师定员叠上去；口数大于 8 的交换机改用加高底图。PC 把机箱正面、指挥台聊天框、机箱背面从左到右拼成一条，背面用与交换机相同的 RJ45 叠加并可接线。已经填了的对端用逻辑线指到信息框，框内只显示对端设备与端口号。两端互指成功后，端口和信息框两侧同时亮绿点。对端端口编号由学生手输。教师与学生壳使用深色指挥台：navy 底、青绿描边、玻璃面板，拓扑/机箱做主舞台。
教师端拓扑使用逻辑网络设备图标：路由器、交换机、PC、特殊双口交换机各有示意符号，端口与 IP 用文字标在图标旁。链路样式区分已连通与单端填写。

## 2. 图层

学生设备舞台自下而上四层：

1. 设备底图
2. RJ45 端口叠加（交换机、路由器、特殊双口交换机、PC 机箱背面）
3. 逻辑连线
4. 对端信息框与连通指示

## 3. 素材

| 角色 | 底图 | 叠加端口 |
| --- | --- | --- |
| 交换机 | 无网口灰色交换机正面图；`port_count` 大于 8 时改用加高底图 | `port_count` 个 RJ45 |
| 路由器 | 无网口灰色路由器正面图 | `port_count` 个 RJ45 |
| PC | 机箱正面 + 聊天框 + 机箱背面 | 背面 1 个 RJ45 |
| 特殊双口交换机 | 与交换机相同底图 | 固定 2 个 RJ45 |

上表仅用于学生端。教师端逻辑图标由前端内联 SVG 绘制。

## 4. 端口布置

交换机与路由器：在机箱前面板空白带内水平均分 RJ45。端口数小于等于 8 时单排；大于 8 时两排。每个 RJ45 下方或内部标注 `port_id`（例如 `S1/01`）。
目标课堂场景中路由器通常为 2 口，叠加数量以教师填写的 `port_count` 为准。

PC：机箱背面 I/O 区叠加 1 个 RJ45 作为唯一端口，旁注 `port_id`。

特殊双口交换机：两口并排，端口编号由系统按 TAP 设备 id 生成；对端由教师挂接写入，学生画面只读。

点击 RJ45 打开该口配置：对端端口编号用手输（例如 `S1/01`）；PC 另含 IP 与网关；路由器口另含 IP。掩码固定展示 `255.255.255.0`。已接线端口被其它设备填为对端时提示「端口已被占用」。

## 5. 逻辑线与对端信息框

本口已填写 `peer_port_id` 时，从该端口中心拉一条逻辑线，指向舞台右侧对应的对端信息框。PC 的端口中心为机箱背面 RJ45 的中心。

信息框字段：

| 字段 | 来源 |
| --- | --- |
| 对端端口编号 | `peer_port_id` |
| 对端设备编号 | 从对端 `port_id` 解析出的设备 id |

本口未填对端：该口无线、无信息框。
信息框按端口序号自上而下排列，避免交叉。

## 6. 物理连通绿点

| 条件 | 画面 |
| --- | --- |
| `physically_up` 为 true | 端口右上角绿点，信息框左侧绿点，逻辑线改为绿色 |
| 已填对端且尚未互指 | 逻辑线与信息框保留，连通指示关闭 |
| 未填对端 | 仅底图与本口（交换机/路由器/PC 背面为叠加 RJ45） |

绿点颜色 `#22c55e`。教师拓扑的链路样式见第 8 节。

## 7. 学生角色分区

公共页头：角色名称、设备 id、当前模式（普通 / 模拟）。

| 角色 | 主区 | 辅区 |
| --- | --- | --- |
| 交换机 | 底图 + 多口叠加 + 逻辑线 | MAC 地址表；模拟模式选口转发 |
| 路由器 | 底图 + 多口叠加 + 每口 IP | ARP 表、ping；模拟模式按目的 IP 选口 |
| PC | 机箱正面、指挥台聊天框、机箱背面紧密横排 | IP / 网关、ARP 表、模拟组帧；聊天框内发起聊天与 ping |
| TAP | 交换机底图 + 两口 | 过路帧列表，自动转发 |

等待领取：「请等待教师确定本课设备」
角色领完：「本课设备已领完，请看教师屏」

TAP 是冻结需求里的「特殊双口交换机」：教师把它串到已有链路上，两口自动转发并保存过路帧，其它角色配置对端时把它视为透明。学生端 TAP 使用交换机底图并叠加 2 个 RJ45；教师端 TAP 使用逻辑 SVG 图标。路由器使用路由器底图，按 `port_count` 叠加 RJ45。

PC 聊天为指挥台风：深色气泡、青描边按钮；点「发起聊天」后输入对方 IP；消息发到该 IP。该 IP 不可达时，聊天窗口用红底提示「消息发送失败，对方 IP 不可达」。对话框上的 ping 针对当前聊天对象，结果写入对话窗口。

## 8. 教师画面
定员表：各角色数量，交换机 / 路由器端口数，可选预置路由器口 IP。开放领取后收起定员表，只保留「结束课堂」；结束当前课堂后定员表再出现。

拓扑画布使用逻辑网络设备图标：

| 角色 | 示意 |
| --- | --- |
| 路由器 | 圆角矩形，标记 R，旁注各口编号与 IP |
| 交换机 | 扁矩形，底边短竖线表示端口规模 |
| PC | 显示器外形，旁注主机编号与 IP |
| TAP | 挂在链路线段中点的双口菱形 |

互指成功的链路为绿色实线；单端填写为灰色虚线。放置 TAP 时点选已有链路。模式开关：普通 / 模拟。快照与增量到达后刷新逻辑图标标注与链路样式。设备图标可拖动，连线随节点位置更新。

## 9. 实现约束

教师与学生各一个 Vite + TypeScript 静态入口，目录 `web/teacher`、`web/student`。开发服务器 `allowedHosts` 包含 `.monkeycode-ai.online`。预览只暴露前端一端口时，把 `/api` 与 `/ws` 反代到教师机。

静态资源可缓存。课堂带宽按 3 Mbps 验收：配置变更走增量事件；占位原图仅开发使用，上课堂前换成轻量 SVG。

## 12. 对话框

定员、接线、配地址、模拟选口改为居中玻璃对话框，背景岗位保留。效果图在 `docs/design/dialog-*.png`。

| 时机 | 对话框 | 字段 |
| --- | --- | --- |
| 课前教师 | 确定本课设备 | 课堂名称；PC / 交换机 / 路由器 / 网络分流器台数；交换机口数；路由器口数；可选预置路由口 IP；载入目标课堂 / 创建课堂 / 开放领取 |
| 学生点 RJ45 | 填写对端端口 | 本口只读；对端端口手输；保存 / 清除对端。占用提示「端口已被占用」 |
| 学生 PC 或路由器口 | 配置 IP | IP；掩码只读 `255.255.255.0`；PC 另含网关 |
| 模拟·交换机收到帧 | 转发数据帧 | 帧字段含数据摘要；按目的 MAC 点选出端口后转发 |
| 模拟·路由器收到帧 | 转发数据帧 | 帧字段含数据摘要；按目的 IP 点选出端口后转发；选对后改写 MAC |

选错出口时在同一对话框提示「端口不正确」，帧留在本机。
