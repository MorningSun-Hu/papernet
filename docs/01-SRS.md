## 1. 项目概述

### 1.1 项目背景

初中课堂需要把「看不见的网络」变成可操作的岗位：每人扮演一台设备，先连线配地址，再一跳一跳传汉字报文。纸上谈网（PaperNet）提供教师机课堂中心与学生机角色端，在课桌上拼成一张网并推演通信。

### 1.2 项目目标

1. 教师生成路由器、交换机、PC、特殊双口交换机的数量与端口规模，学生随机领取，领完即止。
2. 学生配置端口互指、IP、网关；物理连通后直接显示 MAC 地址表或 ARP 表。
3. 普通模式由教师机判定可达并转发文字与 ping。
4. 模拟模式由学生按跳选端口转发简化网络帧；路由器转发时系统改写 MAC。
5. 支持独立学生端与托管学生端；教师机维持不少于 100 条同时在线连接。
6. 服务器部署时教师机与学生机同机，Nginx 反代；规格按 2 核 2G、3 Mbps 固定带宽验收。

效力：本章是需求的结构化转写。与冻结的 `requirements.md` 冲突时，以 `requirements.md` 为准。

### 1.3 术语

以需求文档 Glossary 为准。补充：

- **课堂**：一次上课会话，含角色池、拓扑、模式（普通/模拟）。
- **连接**：一条学生端会话（独立进程或浏览器连接），最多领取一个角色。
- **可达**：教师机按 Requirement 9 判定的通信结果。

### 1.4 目标课堂场景

系统应当支持：`PCA — 交换机1 — 路由器(R1/01、R1/02) — 交换机2 — PCB`。PCA 与 R1/01 同一 C 类网段，PCB 与 R1/02 另一 C 类网段。PCA 网关为 R1/01 的 IP，PCB 网关为 R1/02 的 IP。普通模式可文字互发与 ping；模拟模式可逐跳把帧从 PCA 传到 PCB 并原路回复。

## 2. 系统用户与角色

### 2.1 用户类型

| 用户 | 入口 | 职责 |
| --- | --- | --- |
| 教师 | 教师 Web | 定员、看拓扑、放特殊双口、开模拟模式 |
| 学生 | 独立学生端或托管学生端 | 领角色、配端口与地址、聊天、ping、选端口转发 |

### 2.2 设备角色

| 角色 | 界面要点 |
| --- | --- |
| PC | 网卡图标、IP、网关、对端端口、对话窗口、ping |
| 交换机 | 多端口、对端端口、MAC 地址表、模拟模式选口转发 |
| 路由器 | 多端口、每口 IP、ARP 表、ping、模拟模式按目的 IP 选口 |
| 特殊双口交换机 | 两端口由教师串路、自动转发、保存过路帧 |

无登录账号体系、无学校组织权限模型。身份就是「当前课堂里的教师连接 / 学生连接」。

## 3. 课堂与领取

1. 教师确认各角色数量及路由器/交换机端口数之前，学生接入只提示等待教师确定本课设备，不领角色。
2. 教师确认后开始随机领取；此前已在等待的连接立即参与领取。一个连接一个角色，领完即止。断线后已领角色仍占用，不发给后来者；学生用原 connection_id 重连恢复。
3. 角色耗尽后的提示文案固定为：**本课设备已领完，请看教师屏。**
4. 独立学生端 PC 使用本机网卡真实 MAC；托管学生端 PC 由系统生成真实格式 MAC。
5. 独立端与托管端共用同一角色池。

对应需求：Requirement 1、2、17。

## 4. 组网配置

1. 端口编号：`R1/01`、`S3/01`。
2. 两端都填写对方端口编号后，该链路为物理连通。
3. 掩码固定展示 `255.255.255.0`，修改操作保持该值。
4. 学生填写 PC/路由器 IP 与 PC 网关；教师可预置路由器口 IP。
5. 每次配置同步到教师机，教师机刷新拓扑并回推连通状态。
6. 特殊双口由教师挂到已有链路上；其它角色对端选项只出现链路两端端口。

对应需求：Requirement 3、4、5、14。

## 5. 表项显示

1. 交换机：物理连通后立即出现 MAC 地址表（端口 ↔ 对端 MAC）。
2. PC/路由器：本口已有 IP 且物理连通后立即出现同网段 ARP；PC 网关填好且到网关链路连通后出现网关 ARP。
3. 不演示空表学习与 ARP 询问动画。

对应需求：Requirement 6。

## 6. 普通模式通信

1. PC 对话窗口按目的 IP 发汉字，一对多。
2. 教师机按 Requirement 9 判定可达后投递。
3. PC 与路由器提供 ping；可达给虚拟响应，不可达给失败信息。
4. 跨网段必须网关填写为通往目的网段的路由器近端口 IP。

对应需求：Requirement 7、8、9。

## 7. 模拟模式

1. 教师开启后全员进入模拟模式，沿用已搭建拓扑与表项。
2. 发送端组帧：目的 MAC、源 MAC、源 IP、目的 IP、汉字消息体；帧头与数据区分开标识。
3. 同网段目的 MAC 用目的 IP 的 MAC；跨网段用网关 MAC。
4. 交换机学生按目的 MAC 选口；选错则帧留在本机并提示端口不正确。
5. 路由器学生按目的 IP 选口；选对后系统改写源/目的 MAC 再转出。
6. 正确转发后本机结束该帧展示（特殊双口除外）。
7. 特殊双口一收一转并保存全部过路帧。
8. 多对 PC 可同时按同一规则传帧；回复走同一套组帧与逐跳。

对应需求：Requirement 10–15。

## 8. 部署与容量

| 项 | 要求 |
| --- | --- |
| 实现 | 教师机、学生机 Rust；界面 Web |
| 独立学生端 | 每台学生电脑一个进程，一个进程一个角色 |
| 托管学生端 | 学生 UI 在服务器，一条连接一个角色 |
| 并发 | 教师机同时维持不少于 100 条学生连接，完成领取、同步、转发、传帧 |
| 同机部署 | 教师机与学生机同一服务器，Nginx 反代 Web 入口 |
| 验收规格 | 2 核 CPU、2 GB 内存、3 Mbps 固定带宽 |

对应需求：Requirement 16、17、18。

## 9. 非功能需求

1. 3 Mbps 下禁止全量拓扑轮询；配置变更走增量事件。
2. 静态图标与前端资源可缓存。
3. 2 GB 内存下课堂状态以内存为主，持久化只保存课堂快照，不保存多媒体。
4. 无第三方登录；不建用户表权限模型。本期不实施课堂码，学生加入当前课堂。

## 10. 范围外

- 以太网类型字段、校验和、TTL、ICMP 二进制。
- 动态路由、VLAN、NAT、DNS、DHCP。
- 学生改掩码、交换机口配 IP、交换机口自用通信 MAC。
- ARP 请求/应答动画。
- 账号体系、多租户、成绩系统。
- 课堂码 / 课堂口令（本期不实施）。
