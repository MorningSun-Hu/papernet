## 1. 文档说明

### 1.1 设计目标

教师机对外提供唯一 API。独立学生端与托管学生端走同一套接口。界面通过 Nginx 进入，浏览器与本地客户端都使用 JSON。

### 1.2 设计原则

1. 写操作走 HTTP；课堂状态变化走 WebSocket 增量事件，避免 100 路客户端轮询。
2. 一条学生连接最多绑定一个 `device_id`。
3. 教师连接与学生连接用 `role=teacher|student` 区分，不引入用户权限矩阵。
4. 报文与配置体保持短字段名，适配 3 Mbps。

### 1.3 术语

| 名 | 含义 |
| --- | --- |
| classroom_id | 课堂标识 |
| connection_id | 一条 WebSocket 连接 |
| device_id | 角色设备，如 `R1` `S2` `PC3` `TAP1` |
| port_id | 端口编号，如 `R1/01` |
| frame_id | 模拟模式中一帧的唯一编号 |

## 2. 通用接口约定

### 2.1 基础路径与请求格式

| 项 | 约定 |
| --- | --- |
| HTTP 前缀 | `/api/v1` |
| WebSocket | `/ws` |
| Content-Type | `application/json; charset=utf-8` |
| 时间 | UTC，ISO-8601 |

Nginx 将 `/api/`、`/ws` 转到教师机；`/teacher/`、`/student/` 转到对应静态或托管 UI。

### 2.2 统一成功响应

```json
{"ok": true, "data": {}}
```

### 2.3 统一错误响应

```json
{"ok": false, "error": {"code": "CLASSROOM_FULL", "message": "本课设备已领完，请看教师屏"}}
```

无列表分页。课堂内设备上限按教师定员，一次全量快照只在入班时下发一次。

### 2.4 HTTP 状态码

| 状态码 | 使用 |
| --- | --- |
| 200 | 业务成功 |
| 400 | 参数不合法（IP 格式、端口编号） |
| 409 | 业务冲突（角色已领完、选错端口、未开课） |
| 404 | 课堂或设备不存在 |
| 503 | 课堂未就绪 |

### 2.5 通用请求头

| 头 | 说明 |
| --- | --- |
| `X-Classroom-Id` | 课堂 ID |
| `X-Connection-Id` | 入班后服务端颁发 |
| `X-Client-Kind` | `teacher` / `student-standalone` / `student-hosted` |

### 2.6 入班

本期不实施课堂码。默认同时一个活跃课堂。学生加入当前课堂，请求体只带客户端类型。不使用 OAuth。

## 3. 课堂与角色接口

### 3.1 教师创建课堂

`POST /api/v1/classrooms`

请求：

```json
{
  "title": "八年级1班",
  "inventory": {
    "routers": [{"id": "R1", "port_count": 2, "ports": [{"id": "R1/01", "ip": "192.168.1.1"}, {"id": "R1/02", "ip": "192.168.2.1"}]}],
    "switches": [{"id": "S1", "port_count": 4}, {"id": "S2", "port_count": 4}],
    "pcs": [{"id": "PC1"}, {"id": "PC2"}],
    "taps": [{"id": "TAP1"}]
  }
}
```

路由器口 IP 可省略。响应含 `classroom_id`。此时学生仍不可领角色。

### 3.2 教师确认定员并开放领取

`POST /api/v1/classrooms/{id}/open-claim`

将 `claim_state` 置为 `open`。对已处于 `waiting_open` 的学生连接立即随机分配剩余角色，向领到者推送 `claim.granted`（载荷含 `device` 快照）；仍无空位的等待连接改为 `full`，文案「本课设备已领完，请看教师屏」，然后结束该连接。之后新加入的学生连接才走第 3.3 节即时领取。

### 3.3 学生加入课堂

`POST /api/v1/classrooms/join`

```json
{"client_kind": "student-hosted"}
```

响应分三种 `data.status`：

| status | 含义 | 学生界面 |
| --- | --- | --- |
| `waiting_open` | 教师未确认定员 | 「请等待教师确定本课设备」 |
| `claimed` | 领到角色 | 下发 `device` 全量快照 |
| `full` | 角色已尽 | 「本课设备已领完，请看教师屏」 |

`claimed` 时独立端可在 body 带 `nic_mac`；托管端不传，由服务端生成 MAC。

`waiting_open` 与 `claimed` 均创建 `connection` 并返回 `connection_id`。`full` 不创建长期 connection，HTTP 直接返回后结束。

重连：已领取学生携带原 `connection_id` 再调本接口或升级 WebSocket，恢复同一 `device_id`。已领角色不因断线或心跳超时释放。

### 3.4 健康检查

`GET /api/v1/health` 返回 `{"ok": true, "data": {"status": "up"}}`。

### 3.5 教师查询课堂快照

`GET /api/v1/classrooms/{id}/snapshot`

返回设备、端口、链路、表项、模式、在线连接数。仅教师连接可调。教师屏以快照为底，之后只收事件。

## 4. 拓扑与端口接口

### 4.1 配置端口

`PUT /api/v1/devices/{device_id}/ports/{port_id}`

```json
{"ip": "192.168.1.10", "peer_port_id": "S1/01", "gateway": "192.168.1.1"}
```

`gateway` 仅 PC 有效。交换机口忽略 `ip`/`gateway`。服务端校验：

- 掩码展示固定，请求不得改掩码。
- `peer_port_id` 必须是本课堂已有端口。
- 两端互指后写入物理连通，并立即重算 MAC/ARP 表。

成功后向全课堂推送 `topology.updated`（增量：变更的端口、链路、表项）。

### 4.2 教师放置特殊双口

`POST /api/v1/classrooms/{id}/taps/{tap_id}/attach`

```json
{"link": {"port_a": "S1/02", "port_b": "R1/01"}}
```

该 TAP 串在 `port_a`—`port_b` 上。其它角色对端枚举仍只返回 `S1/02` 与 `R1/01`。

### 4.3 对端候选

`GET /api/v1/ports/peers`

返回可填的端口编号列表，不含 TAP 端口。

## 5. 通信与 ping 接口

仅普通模式接受下列 HTTP；模拟模式改走帧接口。

### 5.1 发送文字

`POST /api/v1/chat`

```json
{"to_ip": "192.168.2.10", "text": "你好"}
```

服务端按 Requirement 9 计算可达。不可达返回 `UNREACHABLE`。可达则向目的 PC 连接推送 `chat.received`，并向源连接推送 `chat.sent`。

仅 `kind=pc` 的连接可调本接口。路由器走 ping，不走文字对话。

### 5.2 ping

`POST /api/v1/ping`

```json
{"to_ip": "192.168.2.1"}
```

仅 PC、路由器可调。响应 `{"reachable": true, "detail": "来自 192.168.2.1 的虚拟响应"}` 或失败信息。

## 6. 模拟模式接口

### 6.1 教师切换模式

`POST /api/v1/classrooms/{id}/mode`

```json
{"mode": "simulation"}
```

`mode` 为 `normal` 或 `simulation`。切换后广播 `mode.changed`。

### 6.2 发送并组帧

`POST /api/v1/sim/send`

```json
{"to_ip": "192.168.2.10", "text": "你好"}
```

服务端生成 `frame_id`，按 ARP 填 MAC，将帧投递到源 PC 所连的下一跳（若中间有 TAP 则先到 TAP 自动转）。源 PC 收到 `frame.built` 用于展示帧头/数据区。

### 6.3 学生转发

`POST /api/v1/sim/frames/{frame_id}/forward`

```json
{"out_port_id": "S1/02"}
```

交换机：`out_port_id` 必须等于 MAC 表中目的 MAC 的端口。  
路由器：`out_port_id` 必须等于目的 IP 所属网段的路由器口；通过后服务端改写 MAC。  
选错：`409`，`code=WRONG_PORT`，`message=端口不正确`，帧仍留在当前设备。  
选对：向下一节点推送 `frame.arrived`，向当前连接推送 `frame.departed`（结束本机展示）。TAP 不调此接口，由服务端自动转并 `frame.logged`。

## 7. WebSocket 事件

连接：`GET /ws?classroom_id=&connection_id=` 升级。

服务端下行事件：

| event | 何时 | 载荷要点 |
| --- | --- | --- |
| `hello` | 连上 | 服务端时间、mode |
| `claim.granted` | 等待中的连接在 open-claim 后领到角色 | device 快照 |
| `claim.full` | 等待中的连接在 open-claim 后仍无空位 | 固定满员文案 |
| `topology.updated` | 端口/链路/表变化 | 增量 patch |
| `mode.changed` | 普通/模拟 | mode |
| `chat.received` / `chat.sent` | 普通模式文字 | from_ip, to_ip, text |
| `frame.built` | 源 PC 组帧 | frame |
| `frame.arrived` | 帧到达某设备 | frame, at_device_id |
| `frame.departed` | 本机转发成功 | frame_id |
| `frame.logged` | TAP 存帧 | frame |
| `classroom.online` | 在线数变化 | count |

客户端上行仅 `heartbeat`。业务写操作一律走 HTTP，便于 Nginx 与错误码统一。ICMP 风格的可达探测走 HTTP `POST /api/v1/ping`，与心跳分名。

帧对象：

```json
{
  "frame_id": "f-01",
  "dst_mac": "aa:bb:cc:dd:ee:01",
  "src_mac": "11:22:33:44:55:66",
  "src_ip": "192.168.1.10",
  "dst_ip": "192.168.2.10",
  "payload": "你好"
}
```

## 8. 错误码

| code | HTTP | 对用户文案 |
| --- | --- | --- |
| `WAITING_OPEN` | 409 | 请等待教师确定本课设备 |
| `CLASSROOM_FULL` | 409 | 本课设备已领完，请看教师屏 |
| `UNREACHABLE` | 409 | 目标不可达 |
| `WRONG_PORT` | 409 | 端口不正确 |
| `BAD_IP` | 400 | IP 地址不正确 |
| `MASK_FIXED` | 400 | 子网掩码为 255.255.255.0 |
| `NOT_OWNER` | 409 | 只能配置本角色端口 |
| `NEED_SIM` | 409 | 请先进入模拟模式 |
| `NEED_NORMAL` | 409 | 当前是模拟模式 |

## 9. 安全、性能与验收

### 9.1 安全

加入当前课堂。连接只能改本 `device_id`。不暴露其它学生连接的 `connection_id` 写权限。不扫描、不存储大模型密钥。

### 9.2 性能

| 指标 | 目标（2C2G / 3Mbps / 100 连接） |
| --- | --- |
| 入班到拿到角色 | 3 秒内 |
| 端口保存到全班增量到达 | 1 秒内 |
| 单条 WS 下行 | 变更 patch 小于 4 KB |
| 教师快照 | 仅入班/刷新一次，之后增量 |
| CPU | 100 连接心跳 + 10 路同时传帧时仍可操作教师屏 |

### 9.3 分层

`http` 入参校验 → `classroom` 领域服务（领取、拓扑、可达、帧）→ `ws_hub` 按设备/连接投递。独立学生端是带本机 MAC 采集的同一 HTTP/WS 客户端。

### 9.4 接口验收

1. 未 open-claim 加入得到 `waiting_open`。
2. 先 waiting 再 open-claim，等待连接收到 `claim.granted` 或 `claim.full`。
3. 领完后再加入得到 `full` 与固定文案。
4. 互指后双方表项立即出现在 snapshot 与 `topology.updated`。
5. 缺网关跨网段 chat/ping 为 `UNREACHABLE`。
6. 模拟模式选错口帧仍在，选对口下一跳收到 `frame.arrived`。
7. `POST /api/v1/chat` 仅 PC 可调。
