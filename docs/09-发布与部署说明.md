# 发布与部署说明

记录日期：2026-10-02

效力：发布方式与本地运行包布局。V1.2 冻结文件保持原文。Docker 打包文件与 `deploy/runtime/` 在 gitignore 中，不入库。

## 1. 资源紧张的服务器：在此编好，服务器只跑

状态：已执行（Linux amd64 预编译运行包）。

课堂运行很轻，吃资源的是编译。1–2 GB 内存用来上课通常够。

本开发环境已编出并放到 `deploy/runtime/`：

- `deploy/runtime/papernet-teacher`：Linux x86_64 glibc 教师机（约 5.4MB）
- `deploy/runtime/teacher/`、`deploy/runtime/student/`：静态页

`deploy/Dockerfile` 只从 `nginx:1.27-bookworm` 起步，COPY `runtime/` 里的产物。构建上下文是 `deploy/` 目录。服务器上 `docker compose up -d --build` 不再编 Rust/Node，第一次拉 Nginx 基础镜像后一般一两分钟。

本环境没有 Docker 守护进程，不能在这里导出镜像 tar。交给服务器的是 `deploy/` 目录（含 `runtime/`）。

目标 Ubuntu 需要 amd64。ARM 跑不了这份二进制。

在服务器上：

```bash
cd deploy
docker compose up -d --build
```

默认对外端口 `8088`，改 compose 里 `"8088:80"` 的左边数字。访问 `/teacher/`、`/student/`。根路径没有首页。

编产物命令（以后更新版本时在本仓库执行）：

```bash
/root/.cargo/bin/cargo build --release -p papernet-teacher
bash scripts/build-web.sh
mkdir -p deploy/runtime
cp target/release/papernet-teacher deploy/runtime/papernet-teacher
cp -a dist/teacher deploy/runtime/teacher
cp -a dist/student deploy/runtime/student
```

## 2. 预览用编好的静态页，少走 Vite

状态：已执行。

教师机在发现静态页时，同一端口同时提供 `/api`、`/ws`、`/teacher/`、`/student/`，形态与正式部署相同。查找顺序：环境变量 `PAPERNET_UI_DIR`，否则当前目录或 exe 旁边的 `teacher/index.html` 与 `student/index.html`。未找到静态页时仍只提供接口（Docker 里继续由 Nginx 托管页面）。

本环境预览：

```bash
/root/.cargo/bin/cargo build --release -p papernet-teacher
bash scripts/build-web.sh
bash scripts/preview-static.sh
```

默认 `http://127.0.0.1:8088/teacher/` 与 `/student/`。数据目录默认仓库内 `data/`。

## 3. Windows 教室：教师机一个程序，学生用浏览器

状态：已执行（交叉编译脚本与教室包布局）。

教师电脑（Windows 10+ 64 位）跑一个文件夹：`papernet-teacher.exe` + `teacher/` + `student/` + `启动教室.bat`。老师打开 `http://本机IP:8088/teacher/`，学生用浏览器打开同一地址的 `/student/`。学生不用装程序。

`file://` 打开 HTML 访问不了接口。仓库里的 `papernet-student` 是 Linux 无界面客户端。

在本仓库打包（需 `gcc-mingw-w64-x86-64`）：

```bash
bash scripts/pack-windows.sh
```

产物在 `deploy/windows/`（gitignore，不入库）。把整个文件夹拷到教师电脑后双击 `启动教室.bat`。改端口只改 bat 里 `PAPERNET_BIND` 的左边数字对应端口。
