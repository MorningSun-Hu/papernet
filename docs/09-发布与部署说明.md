# 发布与部署说明

记录日期：2026-10-02

效力：记录已对齐的发布方式，供后续按条执行。本文不改业务代码。V1.2 冻结文件保持原文。

## 1. 资源紧张的服务器：在此编好，服务器只跑

课堂运行很轻，吃资源的是编译。1–2 GB 内存用来上课通常够，用来在服务器上现场 `docker compose build`（Rust + Node）往往不够。

这个开发环境是 `x86_64-unknown-linux-gnu`，可以在这里编出：

- Linux 教师机程序 `papernet-teacher`
- 教师端 / 学生端静态页 `dist/teacher`、`dist/student`

服务器改用「只拷贝现成文件 + 跑 Nginx」的运行镜像：不必再装 Rust/Node，也不再现场编译。第一次拉 Nginx 基础镜像之后，启动只要几秒到一两分钟。

这个环境没有 Docker 守护进程，不能在这里直接导出 `docker save` 镜像 tar。交给服务器的是：编好的 Linux 程序、`dist/` 网页、一份很薄的运行用 Dockerfile（文件放在 `deploy/`，本地 gitignore）。

目标 Ubuntu 需要是 amd64。ARM 机器跑不了这份二进制。

后续执行：在此编好产物，把运行层 Docker 文件改成只 COPY 产物，再写进部署教程。

## 2. 预览用编好的静态页，少走 Vite

教师机进程只提供 `/api` 和 `/ws`，不托管页面。此前预览用 Vite 开发服务器再反代后端。本预览环境只对外开一个端口，后端没起来、挂了或代理目标不对时，浏览器容易 503。

更稳的预览：在此编好静态页，用 Nginx（或同类反代）托管 `/teacher/`、`/student/`，并把 `/api/`、`/ws` 转到教师机。形态与正式部署相同。

环境休眠或进程退出时页面仍会打不开，那是进程没在跑。

后续执行：预览改为静态页 + 教师机 + 反代，入口走前端端口。

## 3. Windows 教室：教师机一个程序，学生用浏览器

教师机是课堂权威（领取、接线、模拟、WebSocket）。学生端是连上教师机的页面。运行时压力在教师机进程上。学生改成独立程序后，领取和模拟仍然打到教师机，教师机该算的还是那些。

目标教室形态：

- 教师电脑（Windows 10+）跑一个教师端：教师机程序 + 两套静态页 + 内置或附带的网页服务
- 老师打开 `http://本机IP:端口/teacher/`
- 学生用 Edge/Chrome 打开同一个地址的 `/student/`，不用装程序

HTML 不能当文件双击打开，`file://` 访问不了接口。仓库里的 `papernet-student` 是 Linux 下采集网卡 MAC 并加入课堂的无界面客户端，不能当 Windows 学生 GUI 用。

Windows 安装包需要交叉编译 `.exe`（或在 Windows 上编）。教室教师机优先用原生程序，Docker Desktop 偏重。

后续执行：先做 Linux 预编译部署（第 1 条），再评估 Windows 教师端打包。

## 4. Docker 文件位置

本地 Docker 打包文件在 `deploy/`（gitignore，不入库）：

- `deploy/Dockerfile`
- `deploy/docker-compose.yml`（构建上下文为仓库根目录）
- `deploy/.dockerignore`、`deploy/Dockerfile.dockerignore`
- `deploy/docker-entrypoint.sh`
- `deploy/DOCKER.md`
- `deploy/Ubuntu-26.04-Docker部署教程.html`

`deploy/nginx.conf` 已在仓库中。构建与启动在 `deploy/` 目录执行：`docker compose up -d --build`。对外端口只改 compose 里 `"主机端口:80"` 的左边数字。
