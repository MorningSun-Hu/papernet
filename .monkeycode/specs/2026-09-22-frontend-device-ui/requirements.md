# Requirements Document: 学生端设备展示与教师端逻辑拓扑

Feature Name: frontend-device-ui
Created: 2026-09-22
Status: 草案，待用户确认

## Introduction

本文件细化冻结需求 R1–R15 中的界面呈现条款，以及 tasklist 第 13 项。产品需求仍以 `.monkeycode/specs/2026-09-19-classroom-network-sim/requirements.md` 为最高效力。学生端交换机与路由器用无网口底图叠加 RJ45；PC 用机箱正面、聊天框、机箱背面横排；各角色用逻辑线与连通指示表达对端。教师端拓扑用逻辑网络设备图标。

## Glossary

- **设备底图**：交换机与路由器使用不含网口的正面机箱图；口数大于 8 的交换机使用加高底图。PC 使用机箱正面图与机箱背面图，中间夹指挥台聊天框。
- **端口叠加**：叠在交换机、路由器底图前面板或 PC 机箱背面上的 RJ45 端口图。交换机与路由器数量由 `port_count` 决定；PC 背面叠加 1 个 RJ45。
- **逻辑线**：从本机某端口指向该端口对端信息框的示意线，表示配置关系。
- **对端信息框**：展示对端设备编号与对端端口编号的卡片。
- **连通指示**：物理连通成立时出现在端口侧与信息框侧的绿色圆点。
- **未连通状态**：已填写对端但尚未互指完成时，逻辑线与信息框保留，连通指示关闭。
- **逻辑网络设备图标**：教师拓扑使用的示意符号，按路由器、交换机、PC、特殊双口交换机四种角色区分，用于表达逻辑拓扑关系。

## Requirements

### Requirement F1

**User Story:** 作为领取交换机的学生，我希望看到无网口机箱和教师设定数量的网口，以便按口接线。

#### Acceptance Criteria

1. 当学生机领到交换机角色时，学生机应当展示交换机设备底图。
2. 当该交换机的 `port_count` 为 N 时，学生机应当在设备底图上展示 N 个 RJ45 端口。
3. 当学生机展示交换机端口时，每个端口应当标明该端口的 `port_id`。
4. 当该交换机的 `port_count` 大于 8 时，学生机应当改用加高交换机底图。

### Requirement F2

**User Story:** 作为领取路由器的学生，我希望看到无网口机箱和教师设定数量的网口，以便按口配置地址和对端。

#### Acceptance Criteria

1. 当学生机领到路由器角色时，学生机应当展示路由器设备底图。
2. 当该路由器的 `port_count` 为 N 时，学生机应当在设备底图上展示 N 个 RJ45 端口。
3. 当学生机展示路由器端口时，每个端口应当标明该端口的 `port_id`。

### Requirement F3

**User Story:** 作为领取 PC 的学生，我希望看到机箱正面、聊天框和机箱背面拼成的岗位，以便在背面接线并在中间发消息。

#### Acceptance Criteria

1. 当学生机领到 PC 角色时，学生机应当从左到右紧密展示机箱正面矢量图、聊天框、机箱背面矢量图。
2. 当学生机展示 PC 时，学生机应当在机箱背面叠加 1 个 RJ45 作为该 PC 的唯一端口，并标明该端口的 `port_id`。
3. 当学生在 PC 聊天框点击「发起聊天」时，学生机应当弹出输入对方 IP 的对话框。
4. 当对方 IP 不可达时，学生机应当在聊天窗口用红底展示「消息发送失败，对方 IP 不可达」。
5. 当学生点击对话框上的 ping 时，学生机应当 ping 当前聊天对象，并把结果写入对话窗口。

### Requirement F4

**User Story:** 作为领取特殊双口交换机的学生，我希望看到两个端口，以便观察教师挂接链路上的过路帧。

#### Acceptance Criteria

1. 当学生机领到特殊双口交换机角色时，学生机应当展示与交换机相同的设备底图。
2. 当学生机展示特殊双口交换机时，学生机应当在设备底图上展示 2 个 RJ45 端口，并标明各端口的 `port_id`。

### Requirement F5

**User Story:** 作为已领取角色的学生，我希望每个已接线端口用逻辑线指向对端信息，以便看清本口连到谁。

#### Acceptance Criteria

1. 当本机某端口已填写 `peer_port_id` 时，学生机应当从该端口引出一条逻辑线，指向该端口的对端信息框。
2. 当学生机展示对端信息框时，信息框应当显示对端 `port_id`。
3. 当对端设备已分配 `device_id` 时，信息框应当显示该对端 `device_id`。
4. 当本机某端口尚未填写 `peer_port_id` 时，学生机应当保持该端口处于无逻辑线、无对端信息框的状态。
5. 当学生填写对端端口编号时，学生机应当提供文本输入框。

### Requirement F6

**User Story:** 作为已领取角色的学生，我希望物理连通时在端口和对端信息框两侧同时看到绿点，以便确认互指成功。

#### Acceptance Criteria

1. 当该端口所属链路 `physically_up` 为 true 时，学生机应当在该端口侧显示绿色圆点。
2. 当该端口所属链路 `physically_up` 为 true 时，学生机应当在对应信息框侧显示绿色圆点。
3. 当该端口已填写对端且所属链路 `physically_up` 为 false 时，学生机应当继续展示逻辑线与对端信息框，并将连通指示保持为未连通状态。

### Requirement F7

**User Story:** 作为教师，我希望在拓扑上看到逻辑网络设备图标，以便从全班视角掌握组网关系。

#### Acceptance Criteria

1. 当教师机展示拓扑中的设备时，教师机应当按该设备角色展示对应的逻辑网络设备图标，并标明 `device_id`。
2. 当教师机展示拓扑中的端口信息时，教师机应当在该逻辑图标旁以文字标注 `port_id` 与已配置的 IP。
3. 当链路 `physically_up` 为 true 时，教师机应当把该链路展示为已连接样式。
4. 当仅有一端填写对端时，教师机应当把该配置保留在拓扑上，并将该链路展示为未物理连通样式。
5. 当教师将特殊双口交换机放置到某条链路上时，教师机应当在该链路上展示特殊双口交换机的逻辑图标。
6. 当教师拖动拓扑中的设备图标时，教师机应当更新该节点位置，并使连线跟随该节点。

### Requirement F8

**User Story:** 作为尚未领到角色或领完后进来的学生，我希望看到固定文案，以便知道当前课堂状态。

#### Acceptance Criteria

1. 当教师尚未确认各角色数量时，学生端应当展示「请等待教师确定本课设备」。
2. 当全部角色已被领取后，后续接入的学生端应当展示「本课设备已领完，请看教师屏」。

### Requirement F9

**User Story:** 作为接线的学生，我希望已被占用的端口被拒绝，以免把线插到别人正在用的口上。

#### Acceptance Criteria

1. 当目标端口已填写 `peer_port_id` 指向其它设备，或已有其它端口指向该目标时，学生机保存对端应当收到「端口已被占用」。
2. 当本口原对端再次指向同一目标端口时，学生机应当允许保存。

### Requirement F10

**User Story:** 作为教师，我希望开放领取后定员表收起，以免误改本课设备。

#### Acceptance Criteria

1. 当课堂领取状态为 open 或 full 时，教师机应当收起定员表，并展示「结束课堂」。
2. 当教师结束当前课堂后，教师机应当再次展示定员表。
