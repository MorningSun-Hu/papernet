# Requirements Document: 纸上谈网网络推演模拟系统

## Introduction

纸上谈网网络推演模拟系统（短名：纸上谈网）是面向初中课堂的网络拓扑与通信推演教学工具。教师机作为课堂服务器，学生机作为客户端。教师先生成路由器、交换机、PC、特殊双口交换机等设备；学生接入后随机领取一个设备角色，在各自界面上配置端口连线、IP 与网关。双方端口互指成功后形成物理连通，教师机汇总并展示拓扑。物理连通且地址配齐后，对应设备直接显示 MAC 地址表或 ARP 表。普通模式下，PC 之间按 IP 收发文字、PC 与路由器发起 ping，报文由教师机按拓扑转发。教师开启模拟模式后，学生按跳传递网络帧：交换机学生按目的 MAC 选端口，路由器学生按目的 IP 选端口，系统在路由器转发时改写 MAC。目标课堂场景为 PCA — 交换机1 — 路由器 — 交换机2 — PCB 能够互通。

## Glossary

- **纸上谈网**：本系统短名。
- **纸上谈网网络推演模拟系统**：本系统全名，下文称系统。
- **教师机**：课堂服务器端，负责生成设备、汇总拓扑、转发普通模式通信、开启模拟模式、在拓扑中放置特殊双口交换机。
- **学生机**：课堂客户端，领取一个设备角色并完成本角色界面上的配置与操作。
- **角色**：学生机领取后所扮演的网络设备类型，包括 PC、交换机、路由器、特殊双口交换机。
- **端口编号**：设备与端口的唯一标识，格式为设备号加端口号，例如路由器 R1 的 1 号口写作 R1/01，交换机 S3 的 1 号口写作 S3/01。
- **对端端口**：某端口所连接的另一设备端口的端口编号。
- **物理连通**：一条链路上两端端口都已填写对方的端口编号。
- **C 类网**：IPv4 网络，子网掩码固定为 255.255.255.0；不同设备可以使用不同的网络号。
- **网关**：PC 上由学生填写的下一跳 IP，跨网段发送时使用。
- **MAC 地址表**：交换机维护的表，记录端口与对端设备 MAC 的对应关系。
- **ARP 表**：PC 或路由器维护的表，记录 IP 与 MAC 的对应关系。
- **普通模式**：拓扑已搭建时，文字聊天与 ping 由教师机按连通性转发，学生不手动选端口。
- **模拟模式**：教师开启后，网络帧在学生机之间逐跳传递，由学生选择转发端口。
- **网络帧**：模拟用的数据单元，含目的 MAC、源 MAC、源 IP、目的 IP、汉字消息体；帧头与数据区标识清楚。
- **特殊双口交换机**：两个端口的角色，由教师指定串接在已有链路上，一端口收、另一端口立即转出，保存所有经过的帧，对其它角色透明。
- **透明**：其它角色配置对端端口、查看拓扑角色关系时，把特殊双口交换机所在链路当作两端设备直接相连。
- **独立学生端**：在学生电脑上单独运行的客户端，一个客户端进程领取一个角色。
- **托管学生端**：学生界面部署在服务器上，由浏览器连接使用；一条学生连接领取一个角色。
- **本课设备已领完**：角色领完后的提示文案，后续连接不再分配角色。

## Requirements

### Requirement 1

**User Story:** 作为教师，我希望上课前生成设备种类、数量和端口规模，以便全班按同一套拓扑领取角色。

#### Acceptance Criteria

1. 当教师指定路由器、交换机、PC、特殊双口交换机的数量时，教师机应当生成对应数量的设备，并以矢量图标展示每一台设备。
2. 当教师设置某台路由器时，教师机应当要求填写该路由器的端口数量，并为每个端口分配端口编号。
3. 当教师设置某台交换机时，教师机应当要求填写该交换机的端口数量，并为每个端口分配端口编号。
4. 当教师为路由器端口填写 IP 时，教师机应当保存该 IP，并在领取该路由器的学生机上直接显示该 IP。
5. 当教师未填写某路由器端口 IP 时，领取该路由器的学生机应当允许学生为该端口填写 IP。

### Requirement 2

**User Story:** 作为学生，我希望接入课堂后随机领到一个尚未分配的设备角色，以便在真实分工下完成组网。

#### Acceptance Criteria

1. 当学生机成功连接到教师机时，教师机应当从尚未领取的设备角色中随机分配一个角色给学生机。
2. 当学生机领到角色时，学生机应当展示该角色对应的矢量图标与操作界面。
3. 当教师尚未确认各角色数量时，新接入的学生端应当提示等待教师确定本课设备，并且不领取角色。
4. 当教师确认各角色数量后，教师机应当按该数量接受领取，领完即止。
5. 当全部角色已被领取后，后续接入的学生端应当展示「本课设备已领完，请看教师屏」，并且不领取角色。
6. 当独立学生端领到 PC 角色时，该客户端应当使用本机网卡的真实 MAC 地址作为该 PC 的 MAC。
7. 当托管学生端领到 PC 角色时，系统应当为该 PC 生成符合真实格式的 MAC 地址。

### Requirement 3

**User Story:** 作为领取路由器、交换机或 PC 的学生，我希望给端口指定对端端口，以便把设备连成拓扑。

#### Acceptance Criteria

1. 当学生为某端口填写对端端口编号时，学生机应当把该配置立即同步到教师机。
2. 当一条链路的两端端口都已填写对方的端口编号时，教师机应当将该链路标记为物理连通，并刷新拓扑展示。
3. 当仅有一端填写了对端端口编号时，教师机应当在拓扑上保留该配置信息，并将该链路保持为未物理连通。
4. 当教师机完成拓扑刷新时，教师机应当向已接入的学生机同步最新的端口配置与连通状态。

### Requirement 4

**User Story:** 作为学生，我希望自行配置 IP 和 PC 网关，以便把主机和路由器放到正确的 C 类网段。

#### Acceptance Criteria

1. 当设备显示子网掩码时，系统应当将子网掩码展示为 255.255.255.0。
2. 当用户尝试修改子网掩码时，系统应当继续展示 255.255.255.0。
3. 当学生为 PC 网卡或路由器端口填写 IP 时，学生机应当保存该 IP 并同步到教师机。
4. 当学生为 PC 填写网关 IP 时，学生机应当保存该网关并同步到教师机。
5. 当教师已为某路由器端口预置 IP 时，学生机应当展示该预置 IP 供该端口使用。

### Requirement 5

**User Story:** 作为教师，我希望在教师机上看到完整拓扑和端口信息，以便掌握全班组网进度。

#### Acceptance Criteria

1. 当任何学生机提交端口、IP 或网关配置时，教师机应当刷新拓扑，并展示各设备矢量图标、端口编号、IP 与对端端口。
2. 当链路达到物理连通时，教师机应当在拓扑上把该链路展示为已连接。
3. 当教师将特殊双口交换机放置到某条已存在的链路上时，教师机应当记录该串接关系，并在教师机拓扑中展示该特殊双口交换机。

### Requirement 6

**User Story:** 作为学生，我希望物理连通后直接看到 MAC 地址表或 ARP 表，以便把注意力放在选路和通信上。

#### Acceptance Criteria

1. 当交换机某端口达到物理连通时，该交换机学生机应当在 MAC 地址表中立即显示该端口与对端设备 MAC 的对应关系。
2. 当 PC 或路由器端口已填写 IP 且该端口达到物理连通时，该设备学生机应当在 ARP 表中立即显示同一网段内已配置 IP 的设备的 IP 与 MAC 对应关系。
3. 当 PC 已填写网关 IP，并且该 PC 到网关设备的链路已物理连通时，该 PC 学生机应当在 ARP 表中立即显示网关 IP 与网关 MAC 的对应关系。
4. 当学生机展示交换机界面时，学生机应当展示 MAC 地址表。
5. 当学生机展示 PC 或路由器界面时，学生机应当展示 ARP 表。

### Requirement 7

**User Story:** 作为领取 PC 的学生，我希望在网络连通后按目的 IP 收发汉字消息，以便体验主机之间的通信。

#### Acceptance Criteria

1. 当学生机领到 PC 角色时，学生机应当展示对话窗口和带端口的网卡矢量图标。
2. 当学生在对话窗口填写目的 IP 并发送文字，且教师机判定源 PC 到目的 IP 可达时，教师机应当把该文字投递到目的 IP 对应的 PC 对话窗口。
3. 当目的 PC 收到文字时，该 PC 学生机应当在对话窗口显示收到的内容，并允许学生回复。
4. 当一台 PC 到多个目的 IP 均可达时，该 PC 学生机应当允许与这些目的 IP 分别进行双向文字通信。
5. 普通模式下，PC 学生机应当在对话窗口中展示已发送和已收到的文字。

### Requirement 8

**User Story:** 作为领取 PC 或路由器的学生，我希望对指定 IP 做 ping 测试，以便检查模拟网络是否连通。

#### Acceptance Criteria

1. 当学生机领到 PC 或路由器角色时，学生机应当提供 ping 操作，并允许学生填写目标 IP。
2. 当学生发起 ping 且教师机判定到目标 IP 可达时，学生机应当展示虚拟响应信息。
3. 当学生发起 ping 且教师机判定到目标 IP 不可达时，学生机应当展示失败信息。

### Requirement 9

**User Story:** 作为教师，我希望系统按真实主干过程判断通断，以便跨网段必须填对网关才能通信。

#### Acceptance Criteria

1. 当源设备与目的 IP 在同一 C 类网段，且中间仅经交换机物理连通时，教师机应当判定该次通信可达。
2. 当源 PC 与目的 IP 不在同一 C 类网段，且源 PC 网关填写为通往目的网段的路由器近端端口 IP，并且源 PC、路由器、目的设备沿途物理连通且地址配齐时，教师机应当判定该次通信可达。
3. 当源 PC 未填写网关，或填写的网关 IP 与通往目的网段的路由器近端端口 IP 不一致时，教师机应当判定该次跨网段通信不可达。
4. 当沿途存在未物理连通的链路时，教师机应当判定该次通信不可达。

### Requirement 10

**User Story:** 作为教师，我希望在拓扑搭好后打开模拟模式，以便全班按跳观察数据传递。

#### Acceptance Criteria

1. 当教师开启模拟模式时，教师机应当通知全部已接入学生机进入模拟模式。
2. 当处于模拟模式时，系统应当基于当前已搭建的拓扑、IP、网关、MAC 地址表和 ARP 表传递网络帧。
3. 当多台 PC 同时互发消息时，系统应当按同一套逐跳规则并行处理各次通信。

### Requirement 11

**User Story:** 作为领取 PC 的学生，我希望发送时看到简化网络帧，以便把汉字消息和地址字段对应起来。

#### Acceptance Criteria

1. 当模拟模式下学生在 PC 上发送文字时，该 PC 学生机应当展示一帧，字段包括目的 MAC、源 MAC、源 IP、目的 IP、汉字消息体。
2. 当展示网络帧时，学生机应当把帧头区域与数据区域分开标识。
3. 当组帧时，系统应当按 ARP 表填写目的 MAC 与源 MAC：同一网段使用目的 IP 对应 MAC，跨网段使用网关 MAC。
4. 当消息体写入网络帧时，系统应当保持汉字原文。

### Requirement 12

**User Story:** 作为领取交换机的学生，我希望根据目的 MAC 选择正确端口并转发，以便练习二层转发。

#### Acceptance Criteria

1. 当网络帧到达交换机学生机时，该学生机应当展示该帧的主要字段，并等待学生选择一个端口后执行转发。
2. 当学生选择的端口与 MAC 地址表中目的 MAC 所对应的端口一致时，交换机学生机应当把该帧转到该端口所连接的下一节点。
3. 当学生选择的端口与 MAC 地址表中目的 MAC 所对应的端口不一致时，交换机学生机应当把该帧留在本机，并提示端口不正确。
4. 当交换机完成一次正确转发时，该交换机学生机应当结束该帧在本机的展示。

### Requirement 13

**User Story:** 作为领取路由器的学生，我希望根据目的 IP 选择正确端口并转发，以便练习跨网段转发。

#### Acceptance Criteria

1. 当网络帧到达路由器学生机时，该学生机应当展示该帧的主要字段，并等待学生按目的 IP 选择一个端口后执行转发。
2. 当学生选择的端口与目的 IP 所属网段对应的路由器端口一致时，路由器学生机应当把该帧转到该端口所连接的下一节点。
3. 当学生选择正确端口并执行转发时，系统应当把帧的目的 MAC 改写为下一跳设备 MAC，把源 MAC 改写为该路由器出口 MAC，并保持源 IP、目的 IP 与汉字消息体不变。
4. 当学生选择的端口与目的 IP 所属网段对应的路由器端口不一致时，路由器学生机应当把该帧留在本机，并提示端口不正确。
5. 当路由器完成一次正确转发时，该路由器学生机应当结束该帧在本机的展示。

### Requirement 14

**User Story:** 作为领取特殊双口交换机的学生，我希望自动记录经过本机的全部帧，以便观察链路上的数据而不参与选路。

#### Acceptance Criteria

1. 当学生机领到特殊双口交换机角色时，学生机应当展示两个端口，并由教师机决定该设备串接在哪一条已存在的链路上。
2. 当其它角色配置该链路的对端端口时，系统应当只提供链路两端设备的端口编号作为对端选项。
3. 当网络帧进入特殊双口交换机的一个端口时，该学生机应当立即从另一端口转出该帧，并在本机保存该帧副本。
4. 当特殊双口交换机保存帧时，学生机应当提供查看全部经过本机的网络帧的界面。

### Requirement 15

**User Story:** 作为领取 PC 的学生，我希望对端收到消息后用同一套流程回复，以便完成一次完整的双向通信体验。

#### Acceptance Criteria

1. 当目的 PC 在模拟模式下收到网络帧时，该 PC 学生机应当在对话窗口显示消息体中的汉字。
2. 当目的 PC 在模拟模式下回复文字时，系统应当按 Requirement 11 至 Requirement 14 的同一套组帧与逐跳规则把回复传到源 PC。
3. 模拟模式下，PC 学生机应当在对话窗口中展示已发送和已收到的文字。

### Requirement 16

**User Story:** 作为开发与部署负责人，我希望教师机与学生机都用 Rust 编写、界面用 Web 呈现，以便在课堂浏览器中完成本系统。

#### Acceptance Criteria

1. 当实现教师机时，教师机程序应当使用 Rust 编写，并通过 Web 界面供教师操作。
2. 当实现学生机时，学生机程序应当使用 Rust 编写，并通过 Web 界面供学生操作。

### Requirement 17

**User Story:** 作为部署负责人，我希望学生端能在机房单机运行，也能在服务器上用浏览器打开，以便适配不同教室。

#### Acceptance Criteria

1. 当使用独立学生端时，系统应当允许每台学生电脑运行一个客户端，并且一个客户端领取一个角色。
2. 当使用托管学生端时，系统应当把学生界面部署在服务器上，并且一条学生连接领取一个角色。
3. 当同一课堂同时存在上述两种接入方式时，教师机应当按同一套角色池分配角色，领完即止。

### Requirement 18

**User Story:** 作为部署负责人，我希望教师机在百人课堂下仍能上课，以便把教师端和学生端放在同一台小规格服务器上。

#### Acceptance Criteria

1. 当不少于 100 名学生同时在线时，教师机应当维持这些连接，并完成角色领取、配置同步、普通模式转发与模拟模式传帧。
2. 当采用服务器部署时，教师机与学生机应当部署在同一台服务器上，并由 Nginx 反向代理对外提供 Web 入口。
3. 当服务器为 2 核 CPU、2 GB 内存、3 Mbps 固定带宽时，系统应当支持 Requirement 18 第 1 条的并发课堂。

## Out of Scope

- 真实以太网类型字段、校验和、TTL、ICMP 报文二进制编码。
- 动态路由协议、VLAN、NAT、DNS、DHCP。
- 学生修改子网掩码、为交换机端口配置 IP。
- 交换机端口自用通信 MAC 的配置。
- 空表学习、ARP 请求与应答动画。

## Classroom Scenario

系统应当支持教师生成并完成如下连通场景：PCA — 交换机1 — 路由器(R1/01、R1/02) — 交换机2 — PCB。PCA 与 R1/01 处于同一 C 类网段，PCB 与 R1/02 处于另一 C 类网段。PCA 网关为 R1/01 的 IP，PCB 网关为 R1/02 的 IP。该场景在普通模式下可文字互发与 ping，在模拟模式下可逐跳把帧从 PCA 传到 PCB 并原路回复。
